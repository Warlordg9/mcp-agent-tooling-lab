# Условие задания

Пересказ условия домашнего задания (лекция «Инструменты, навыки и MCP»).

**Как сдавать:** ссылка на репозиторий (или архив) с кодом сервера, тестами, ноутбуком эксперимента и сырыми логами, плюс PDF-отчёт до 3 страниц без приложений. Ключи API в файлы не включать.

## Задача 1. Теория: экономика контекста (2 балла)

На шаге $t$ агент получает системный промпт $S$, описания инструментов $D$ и историю $H_t \approx h t$. Кэшированный префикс $S + D$ стоит долю $\alpha$ обычной цены, $p_{in} = 1$, выходными токенами пренебрегаем.

* (а) Вывести $C \approx \alpha(S+D)T + hT^2/2$ и указать приближение при суммировании истории.
* (б) Посчитать $C$ для $S=2000$, $D=55\,000$, $h=1500$, $T=40$ при $\alpha=1$ и $\alpha=0{,}1$; доля истории; какой рычаг ($D$, $\alpha$ или $h$) даёт наибольшую экономию.
* (в) $d = 300$ токенов на описание. A: все $N$ описаний; B: поиск ($s = 500$) и $k = 5$ найденных описаний. Минимальное целое $N$, при котором B дешевле на каждом шаге (кэш не учитывать).
* (г) Точность B — $\text{Recall@}k(N)\cdot A(k)$, точность A — $A(N)$; $\text{Recall@5} = 0{,}95$, $A(5) = 0{,}90$. При каком $A(N)$ B перестаёт выигрывать? Два фактора, делающих модель оптимистичной для B.

## Задача 2. MCP-сервер для своего домена (3 балла)

Спецификация MCP 2026-07-28 (stateless, `server/discover`, `_meta` в каждом запросе), Python SDK `from mcp.server import MCPServer`.

1. Не меньше 4 инструментов с общим префиксом пространства имён.
2. Закрытые множества — через `enum`, у всех полей есть `description`, `additionalProperties: false`.
3. Параметр `response_format: "concise" | "detailed"`; в README — размер ответа в токенах для обоих режимов на трёх примерах.
4. Ошибки возвращаются как результат с `isError: true` и подсказкой, что исправить (не стектрейс).
5. Состояние домена передаётся явным handle-аргументом, без сессий.
6. Тесты: pytest на каждый инструмент (успех и ошибка) и прогон через MCP Inspector.

Рубрика: сервер работает по 2026-07-28 и тесты проходят (1); дизайн — пространство имён, enum, описания с «когда не использовать», concise/detailed (1); ошибки с подсказкой и handle для состояния (1). Сервер старой версии протокола (`initialize`, `Mcp-Session-Id`) — не больше 1 балла.

## Задача 3. Эксперимент: выбор из N и петли (5 баллов)

**Часть A.** Пул из 100 инструментов (свои + отвлекающие; если отвлекающие сгенерированы, не меньше 20 близки по смыслу). 30 запросов с разметкой. Для $N = 5, 20, 50, 100$ сравнить (A) все $N$ описаний в контексте и (B) поиск top-5 по эмбеддингам; по 3 запуска на запрос. Измерить точность выбора, Recall@5, среднее число входных токенов; 95 % бутстрэп-интервалы для точности с ресэмплингом **запросов**.

**Часть B.** «Нестабильная» версия инструмента: в 50 % вызовов пустой результат без объяснения. 20 задач без LoopGuard и с LoopGuard (3 повтора, окно 6). Доля эпизодов с петлёй (≥ 3 одинаковых вызова подряд или колебание A-B-A-B), средние шаги и токены, доля успеха. Затем заменить пустой ответ подсказкой («ничего не найдено; попробуйте другое значение `date`») и повторить без LoopGuard. Что помогает сильнее — guard в harness или исправление инструмента?

**Отчёт:** график точности от $N$ для A и B с интервалами; таблица токенов; таблица по петлям для трёх условий; три угрозы валидности. Бюджет — до \$3 на небольшой модели, допустима открытая модель через vLLM/Ollama.

Рубрика: протокол записан, отвлекающие правдоподобны (1); точность и Recall@5 с бутстрэпом по запросам, токены (2); петли — три условия, метрики, вывод (1); честность — полный знаменатель, неудачные запуски не выброшены, ограничения названы (1).

**Не принимается:** результаты без сырых логов; точность без упавших или незавершённых запусков; интервалы по запускам вместо запросов (частичный зачёт).
